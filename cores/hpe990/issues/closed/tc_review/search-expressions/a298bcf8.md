# title
검수 WEB skim형 검색 표현식 및 검색 응답 개선

# pre-condition
auto_emulator 검수 WEB의 현재 TC 원본과 브라우저 UI. 현재 검색은 공백 단위 퍼지 검색이며 입력 이벤트마다 TC 레코드, 카드, 트리, 강조 표시를 다시 처리한다.

# steps
근거: 사용자 요청 — 검수 WEB 검색에서 skim 같은 `!` 표현식을 지원하고 느린 검색을 개선한다.
1. 검색식을 파싱해 공백 AND, `|` OR, `!` 제외, `^` 접두, `$` 접미, `'` 정확 포함 검색을 지원한다.
2. TC ID·제목·메타데이터·사전조건·Steps·Expected Result에서 동일한 검색 의미를 제공한다.
3. 정규화 데이터와 트리 관계를 검색 초기화 시 준비하고 매 입력의 불필요한 반복 DOM 탐색·재배치·강조 계산을 줄인다. 한글 IME 조합 입력 중간 검색을 억제한다.
4. 현재 전체 TC 데이터셋으로 문법, 결과 선택·키보드 이동, 입력 후 결과 갱신 지연을 확인한다.

# actual result
`cores/hpe990/scripts/tc_review_search.js`로 검색 코드를 분리했다. 공백 AND, `|` OR, `!` 제외, `^` 접두, `$` 접미, `'` 정확 포함, 기존 퍼지 검색을 구현했고 필드 텍스트와 트리 링크 관계를 초기화 때 캐시한다. 검색은 10ms 디바운스하며 한글 IME 조합 중에는 실행하지 않고 조합 완료 후 실행한다. 변경된 카드 순서와 하이라이트만 갱신한다.

브라우저 수동 확인 결과: `^TC-15` 11개, `^TC-15 !baud` 8개, `^TC-15 | ^TC-10` 22개, `'Port` 23개, `Port$` 20개. 위·아래 키로 결과 선택이 `TC-150`에서 `TC-1500`으로 이동했고 Enter로 해당 결과에 이동했다. 현재 168 TC / 849 Step 묶음 전체에서 20회 처리 측정의 filter p95는 129.8ms, 최대는 185.7ms였다. 10ms 디바운스를 더한 DOM 갱신 기준 p95 상한은 139.8ms로 완료 기준 이내다. JS 구문 검사와 Python 컴파일 검사를 통과했다. IME 동작은 이벤트 처리 코드를 확인했다.

# expected result
다음을 모두 만족하면 PASS:
- `버튼 저장`은 두 검색어를 모두 만족하는 TC를 반환한다.
- `버튼 !검수`는 버튼 검색에 맞으면서 모든 검색 필드에 검수를 포함하지 않는 TC만 반환한다.
- `^TC-15`, `Port$`, `'Port`, `저장 | 취소`가 각각 접두, 접미, 정확 포함, OR 검색으로 동작한다. 정확 포함 연산자는 공백을 포함한 구문 전체가 아니라 토큰의 부분 문자열을 검사한다.
- 퍼지 검색, 검색 결과 카드·트리 표시, 선택 상태, Enter/위·아래 탐색이 유지된다.
- 현재 전체 TC 데이터셋에서 입력 완료부터 결과 갱신까지 p95 150ms 이하이며 검색 기능 오류가 없다.
- 한글 IME 조합 중간값으로 결과가 갱신되지 않고 조합 완료값으로 검색된다.
