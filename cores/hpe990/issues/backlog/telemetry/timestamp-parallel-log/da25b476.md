# title
RAM 수집과 병행하는 timestamp 기반 별도 활동 로그 기록

# pre-condition
- 소유 family: hpe990; function family: telemetry; 프로젝트: auto_emulator.
- 기존 native RAM과 semantic RAM의 events.jsonl, JSON 스냅샷 및 PNG 증거 사용.
- 관련 구현: telemetry/window-change-events/4c1abd34, ui_collection/complete-ui-inventory/50c688e3의 semantic RAM 보완. 기존 이슈의 전체 UI 완료 조건에 의존하지 않음.
- Python은 uv 관리, 고속 처리는 Rust. 구현·증거는 auto_emulator 및 공통 D_TEMP 경로에만 저장하고 pk_system은 수정하지 않음.
- 색상 변화 감지는 유지. 에뮬레이터 설정값 변경이나 배포 EXE 갱신은 이 등록 범위에 포함하지 않음.

# steps
근거: 사용자 지시 2026-10-07: 수집결과 형태는 어떤 형태인가? timestamp 로 그 시기가 추정되는 형태도 로그형식으로 별도 병렬수집 되어야 한다. add issue.
1. 기존 native/semantic 이벤트의 시각 필드와 수집 시점, 지연 및 관찰 공백을 확인하고 로그의 시각 의미를 문서화.
2. 기존 수집과 동시에 별도 activity.log에 사람이 읽을 수 있는 활동 기록을 지속 append. 종료 후 일괄 변환만 수행하는 방식은 병렬 수집으로 인정하지 않음.
3. 각 기록에 시간대 포함 ISO 8601 timestamp와 원본 epoch milliseconds, 관측 시각과 로그 기록 시각, session_id/run_id, 원본 stream/sequence, ui_id(미식별이면 명시), 변화 종류, 전후 내용 및 증거 경로 포함. 원본에 실제 발생 시각이 없으면 관측 시각으로 명시하고 발생 시각을 꾸며내지 않음.
4. 입력값·문구·색상 변화, 화면·모달·팝업 등장/소멸, 수집 시작/종료 및 observation_gap 기록. 늦게 도착한 이벤트도 원본 시각과 순번을 보존하며, 서로 다른 stream의 순번을 동일 순번 체계로 혼동하지 않음.
5. 별도 로그 writer가 기존 RAM/자동제어를 막지 않도록 운영하고 쓰기 실패·누락·재시작 중복을 진단. 로그 시작/상태/조회/정리 기능을 공개 MCP로 제공하고 실제 호출로 검증.
6. 아래 단일 AC를 재현 가능한 관측 이벤트와 실제 MCP 세션으로 검증하고 증거 저장.

# actual result
미구현: 기존 native/semantic events.jsonl에는 observed_unix_ms와 sequence/session_id/run_id가 있고, PNG와 JSON 증거가 별도로 저장된다. 사람이 읽을 수 있는 시간대 포함 timestamp의 별도 activity.log 병렬 수집은 아직 제공하지 않는다. 이번 요청은 이슈 등록만 수행하며 기존 수집 기능과 색상 변화 감지를 변경하지 않음.

# expected result
AC-timestamp-parallel-log: 기존 RAM을 유지하면서 별도 timestamp 활동 로그가 실시간으로 기록되고 원본 이벤트와 추적 가능하면 PASS. 다음 검증 항목을 모두 충족해야 함.
- native/semantic 두 stream을 포함하는 최소 100개 기준 이벤트에 대해 로그 대응 누락 0건, 원본 (stream, run_id, sequence) 중복 0건, 원본 JSONL 비수정 확인.
- 각 기록의 관측 시각·기록 시각·timezone이 파싱 가능하고, 전후 값/문구 또는 색상 변화 요약 및 존재하는 스냅샷/PNG 참조 대조 성공률 100%. 미확정 값과 OCR 결과의 의미 상태를 구분.
- 검증 중 원본 이벤트가 로그 writer에 이용 가능해진 시각부터 append까지 지연 p99 1초 이하를 목표로 실측하고 기록. OCR 지연을 실제 발생 시각으로 오인하지 않음.
- 공개 MCP로 로그 실행/상태/조회/정리를 검증하고, 로그 실행 중 기존 RAM 활성 및 자동제어 동시 동작 확인. 로그 정리는 에뮬레이터와 기존 RAM을 종료하지 않음.
- 관찰 공백·늦은 이벤트·로그 쓰기 실패·재시작을 검증하여 원인과 복구 결과 기록. 숨겨진 손실이나 실패를 정상 무변화로 기록한 경우 FAIL.
- 예시 형식(가상 내용): `2026-10-07T16:32:25.084+09:00 INFO stream=semantic_ram run_id=... sequence=42 ui_id=UI-000083 kind=value_changed before="5" after="6" observed_unix_ms=... recorded_at=... evidence=...`.
- 검증 증거: `{D_TEMP}/hpe990/evidence/da25b476/`의 activity.log, 원본 이벤트 대조표, 지연/손실 보고서 및 실제 MCP 호출 기록. 전 UI·전 순간 변화의 완전 감지 판정과는 구분.
